# 과제 평가 기준

## 제출 목표

다음 제출 패키지를 포함한 웹 서비스 1개를 완성합니다.

필수 제출물:

1. 배포된 웹 서비스 (Vercel URL)
2. GitHub 저장소
3. README.md
4. 서비스 기획서
5. 증빙 자료

## 1. 배포된 웹 서비스

필수 조건:

- 최소 3개 이상의 페이지 또는 섹션이 있고, 메뉴 이동이 가능해야 합니다.
- 반응형으로 모바일에서도 정상 표시되어야 합니다.
- AI API가 연동된 기능이 1개 이상 포함되어야 합니다(입력 → 결과 출력까지).

이 프로젝트(SpeakUp) 적용 기준:

- 한 페이지 안에 Hero(홈) / 연습하기(Part3·Part5) / 학습 안내 / FAQ, 총 4개 섹션을 둡니다.
- 상단 고정 내비게이션으로 섹션 이동을 제공합니다.
- AI 기능 2가지(문제 자동 생성 `/api/generate`, 답변 평가 `/api/evaluate`)가 입력부터 결과 출력까지 동작합니다.

## 2. GitHub 저장소

필수 조건:

- 프로젝트 코드가 GitHub 저장소에 업로드되어 있어야 합니다.
- 프론트엔드(`index.html`, `css/`, `js/`)와 백엔드(`api/`) 구조가 구분되어 있어야 합니다.
- 커밋 이력이 남아 있어야 합니다.

이 프로젝트 구조 기준:

```text
index.html
css/
js/
api/
images/
docs/
requirements.txt
vercel.json
README.md
```

## 3. README.md

README에 반드시 포함할 내용:

- 서비스 소개
- 기술 스택
- 실행 방법
- 배포 방법
- 배포 URL
- 환경 변수 설정 방법

환경 변수 문서화 기준:

- API 키 값은 절대 README에 직접 적지 않습니다.
- 변수 이름과 설정 위치만 설명합니다.
- 예시 값은 실제 키처럼 보이지 않는 더미 값만 사용합니다.

## 4. 서비스 기획서

서비스 기획서에 포함할 내용:

- 서비스 목적
- 타겟 사용자
- 페이지 또는 섹션 구성
- 핵심 기능
- AI 기능의 입력
- AI 기능의 출력
- AI 기능의 실패 처리 기준

이 프로젝트에서는 SDD 문서를 서비스 기획서 제출 자료로 활용합니다.

관련 문서:

- `docs/product-spec.md`
- `docs/user-flows.md`
- `docs/data-model.md`
- `docs/api-spec.md`
- `docs/implementation-plan.md`

## 5. 증빙 자료

필수 증빙:

- 서비스 스크린샷 1세트
- AI 코딩 도구 사용 과정 1세트

서비스 스크린샷 세트:

- 데스크톱 화면
- 모바일 화면
- AI 기능이 실제로 동작하는 장면(문제 생성, 평가 결과 각각 권장)

AI 코딩 도구 사용 과정:

- 대화 로그 또는 스크린샷
- 코드 생성, 수정, 오류 해결 과정이 드러나면 좋습니다.
- API 키나 비밀 값이 노출되지 않아야 합니다.

저장 위치:

```text
docs/evidence/
```

README.md의 "스크린샷", "AI 코딩 도구 사용 과정" 섹션에서 이 폴더의 파일을 참조합니다.

## 과제 목표

과제 완료 후 학습자는 다음을 설명할 수 있어야 합니다.

- HTML, CSS, JavaScript가 각각 어떤 역할을 하는지
- 사용자 입력이 JavaScript의 `fetch` 요청으로 바뀌고, 응답이 화면에 반영되는 흐름
- Vercel Serverless Functions가 무엇인지
- 프론트엔드에서 Python 백엔드를 호출하는 구조
- 환경 변수로 API 키를 안전하게 관리해야 하는 이유
- 로컬 환경과 배포 환경의 차이
- 배포 후 문제를 수정하고 재배포하는 흐름
- AI 코딩 도구로 만든 코드라도 오류 원인과 수정 방향을 설명하는 방법

## 기능 요구 사항

### 서비스 기획

- 웹 서비스 아이디어를 정의합니다.
- 목적과 타겟 사용자를 정의합니다.
- 최소 3개 이상의 페이지 또는 섹션을 설계합니다.
- 메뉴 이동 방식을 정합니다.
- AI 기능 1개 이상을 정의합니다.
- AI 기능의 입력, 출력, 사용자 가치를 정리합니다.

### 프로젝트 초기화 및 구조 구성

- 프로젝트 폴더와 기본 구조를 구성합니다.
- 예시 구조를 따릅니다: `index.html`, `css/`, `js/`, `api/`, `images/`, `requirements.txt`
- GitHub 저장소를 생성합니다.
- 의미 있는 커밋 이력을 남깁니다.

### 프론트엔드 화면 구현

- 순수 HTML, CSS, JavaScript로 구현합니다.
- React, Vue 등 프레임워크를 사용하지 않습니다.
- 메인 및 추가 페이지 또는 섹션을 구현합니다.
- 페이지 또는 섹션 간 내비게이션을 제공합니다.
- 기본 레이아웃과 스타일을 적용합니다.

### 반응형 적용 및 확인

- 모바일, 태블릿, 데스크톱에서 레이아웃이 깨지지 않게 합니다.
- 최소 2가지 화면 크기에서 직접 확인합니다.

### AI 기능 UX 최소 기준

- 사용자 입력을 받는 UI를 제공합니다.
- AI 결과를 화면에 표시합니다.
- 다음 실패 처리 중 최소 1개 이상을 사용자에게 안내합니다.
  - 빈 입력
  - API 오류
  - 지연 또는 타임아웃

이 프로젝트는 세 가지를 모두 처리합니다.

### AI API 연동

- 백엔드는 Vercel Serverless Functions의 Python으로 구현합니다.
- `api/` 폴더에 Python 엔드포인트를 둡니다.
- AI API를 호출한 뒤 결과를 반환합니다.
- 필요한 Python 패키지는 `requirements.txt`에 정의합니다.
- 프론트엔드는 `fetch('/api/...')`로 백엔드를 호출합니다.

### 배포 및 동작 검증

- GitHub와 Vercel을 연동해 배포합니다.
- 배포 URL에서 내비게이션, 반응형, AI 기능을 확인합니다.
- 문제가 있으면 수정 후 재배포합니다.

### 문서화 및 제출 패키지 구성

- README에 소개, 기술 스택, 배포 URL, 실행 방법, 환경 변수를 정리합니다.
- 스크린샷과 AI 코딩 도구 사용 증빙을 준비합니다.
- 서비스 기획서를 제출 패키지에 포함합니다.

## 보너스 과제 (선택)

1. 운영 자동화 또는 데이터 저장 고도화
   - 문의/폼 입력 또는 AI 결과를 외부 도구(예: 노코드 자동화)나 간단한 저장소에 연동합니다.
   - 배움 포인트: "사용자 입력 → 처리 → 저장/알림" 운영 흐름을 서비스 관점으로 확장합니다.
   - 이 프로젝트에서는 Langfuse 연동(AI 호출 trace 저장)을 이 항목의 확장으로 볼 수 있습니다.
2. 사용자 경험(UX) 및 측정 고도화
   - 다크 모드, 마이크로 인터랙션, 방문자 분석 중 1개 이상을 적용합니다.
   - 배움 포인트: 사용성 개선과 개선 효과를 확인하는 방법을 함께 설계합니다.

우선순위:

- MVP 필수 조건을 먼저 완료합니다.
- 보너스는 필수 제출물이 안정적으로 동작한 뒤 진행합니다.

## 개발 환경 제약

- 프론트엔드는 순수 HTML, CSS, JavaScript로 구현합니다.
- React, Vue, Next.js 등 프론트엔드 프레임워크를 사용하지 않습니다.
- 백엔드는 Vercel Serverless Functions의 Python을 사용합니다.
- AI 기능은 최소 1개 이상 포함합니다.

## 보안 및 운영 제약

- API 키는 반드시 환경 변수로 관리하고, 코드/README/스크린샷에 노출하지 않습니다.
- AI API는 과금/쿼터가 발생할 수 있음을 인지하고, 호출 빈도와 실패 상황을 고려합니다.
- 키 유출이 의심되면 즉시 폐기/재발급하고, 노출된 커밋 이력도 정리합니다.
- 템플릿/예시를 그대로 복제하지 않습니다(아이디어·문구·구성 변경 필수).
- 배포 URL에서 동작이 재현 가능해야 합니다(동료가 접속/테스트 가능).
