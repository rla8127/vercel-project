# 구현 계획

## 전제

- 프론트엔드: 순수 HTML, CSS, JavaScript
- 프론트엔드 프레임워크: 사용하지 않음
- 백엔드: Vercel Serverless Functions의 Python
- API 위치: `api/index.py` (FastAPI 앱), 생성 로직 `api/generate.py`, 평가 로직 `api/evaluate.py`
- 프론트엔드 호출 방식: `fetch('/api/generate')`, `fetch('/api/evaluate')`
- 배포: Vercel
- 문제 출처: AI 자동 생성 (정적 문제 은행 없음)
- AI 역할: 문제 생성 + 평가, 모두 OpenAI로 통일
- 답변 입력 방식: 텍스트 입력 (마이크/음성 없음)
- MVP 문제 유형: Part3(대화문 기반 질의응답), Part5(문제 해결하기)
- 작업 서비스명: SpeakUp (이전 TranslateUp 완전 대체)

## 1단계: 문서 및 기존 자산 정리

- SDD 문서(`product-spec.md`, `user-flows.md`, `data-model.md`, `api-spec.md`, 본 문서)를 SpeakUp 기준으로 갱신합니다.
- 기존 TranslateUp 전용 정적 문제 데이터(`data/exercises.json`)는 더 이상 사용하지 않으므로 제거하거나 대체합니다.
- README를 SpeakUp 기준으로 갱신합니다.

완료 기준:

- 모든 SDD 문서가 SpeakUp 기준으로 일관됩니다.
- 더 이상 쓰지 않는 정적 문제 파일이 정리되어 있습니다.

## 2단계: Python 문제 생성 API

- `api/generate.py`에 생성 로직을 구현합니다.
- 요청 본문(`part`)을 검증합니다.
- Part3와 Part5에 맞는 프롬프트를 각각 구성합니다.
- OpenAI Responses API의 `json_schema` 구조화 출력으로 상황/대화/질문(Part3) 또는 상황/문제요약(Part5)을 생성합니다.
- 응답을 정규화하고 검증한 뒤 반환합니다.

완료 기준:

- `part3` 요청 시 상황, 대화문, 질문 3개가 포함된 JSON을 반환합니다.
- `part5` 요청 시 상황 설명과 문제 요약이 포함된 JSON을 반환합니다.
- 잘못된 `part` 값은 `400`을 반환합니다.
- 매 호출마다 내용이 달라지도록 프롬프트에 다양성 지시를 포함합니다.

## 3단계: Python 평가 API

- `api/evaluate.py`를 토익 스피킹 평가 로직으로 재작성합니다.
- 요청 본문(`part`와 관련 필드)을 검증합니다.
- 한글만 입력된 답변, 빈 답변을 서버에서 재검증합니다.
- Part3/Part5에 맞는 평가 프롬프트를 구성합니다.
- OpenAI Responses API의 `json_schema` 구조화 출력으로 점수, 모범 답안, 피드백, 개선 포인트를 생성합니다.
- 응답을 정규화(점수 0-100 clamp 등)하고 검증한 뒤 반환합니다.

완료 기준:

- 유효한 요청은 평가 결과 JSON을 반환합니다.
- 잘못된 요청은 `400`을 반환합니다.
- 제공자 오류 또는 파싱 실패는 `500`을 반환합니다.
- API 키 누락은 통제된 서버 오류로 처리됩니다.

## 4단계: 라우팅 연결

- `api/index.py`에 `/api/generate`, `/api/evaluate` POST 라우트를 추가합니다.
- 각 라우트는 GET 요청에 `405`를 반환합니다.
- 정적 파일 서빙(`StaticFiles`)은 그대로 유지합니다.

완료 기준:

- 두 엔드포인트가 모두 FastAPI 앱에 연결되어 있습니다.
- 루트 URL은 여전히 `index.html`을 표시합니다.

## 5단계: 한 페이지 UI 재구성

- Hero 섹션을 SpeakUp 소개로 교체합니다.
- Part3/Part5 선택 및 연습 섹션을 새로 만듭니다.
- AI 평가 결과 섹션(문항별 카드)을 새로 만듭니다.
- 학습 안내, FAQ 섹션 내용을 토익 스피킹 기준으로 갱신합니다.
- 상단 메뉴/내비게이션 링크를 새 섹션 ID로 갱신합니다.
- 반응형 레이아웃을 유지합니다.

완료 기준:

- 최소 3개 이상의 섹션이 있습니다.
- 메뉴 이동이 가능합니다.
- 모바일과 데스크톱에서 레이아웃이 깨지지 않습니다.

## 6단계: 프론트엔드 상호작용

- Part 선택 UI를 구현합니다.
- "문제 만들기" 버튼과 로딩 상태를 구현합니다.
- Part3: 질문 3개 각각에 답변 입력창 + 개별 평가 버튼을 렌더링합니다.
- Part5: 단일 답변 입력창 + 평가 버튼을 렌더링합니다.
- 입력 검증(빈 답변, 한글만 입력)을 구현합니다.
- 문항별 로딩/오류/성공 상태를 독립적으로 관리합니다.
- 평가 결과를 원본 JSON이 아닌 사용자 친화적인 카드 UI로 표시합니다.

완료 기준:

- Part 미선택 상태에서 진행이 막힙니다.
- 빈 답변 제출이 막힙니다.
- 한글만 입력한 답변 제출이 막힙니다.
- 평가 중 중복 제출이 막힙니다(문항 단위).
- 생성 실패, 평가 실패 메시지가 각각 표시됩니다.

## 7단계: 정적 문제 데이터 정리

- `data/exercises.json`은 더 이상 사용하지 않으므로 삭제합니다.
- `data/` 폴더 자체는 향후 확장을 위해 유지하되, MVP에서는 비어 있을 수 있습니다.

완료 기준:

- 프론트엔드 코드에서 `data/exercises.json`을 더 이상 참조하지 않습니다.

## 8단계: README와 제출 문서

- README를 SpeakUp 기준으로 갱신합니다(소개, 기술 스택, 실행 방법, 배포 방법, 배포 URL, 환경 변수).
- SDD 문서를 서비스 기획서 제출 자료로 최종 정리합니다.

완료 기준:

- README가 과제 필수 항목을 모두 포함합니다.
- API 키 값이 README나 문서에 노출되지 않습니다.

## 9단계: 검증

- 정적 페이지 렌더링을 확인합니다.
- Python API를 로컬(`vercel dev` 또는 `uvicorn`) 또는 Vercel Preview에서 확인합니다.
- 다음 항목을 수동으로 확인합니다.
  - 메뉴 이동
  - 모바일 레이아웃
  - 데스크톱 레이아웃
  - Part3 문제 생성 및 질문 3개 개별 평가
  - Part5 문제 생성 및 평가
  - 빈 답변 / 한글만 입력 검증
  - 생성 실패 / 평가 실패 표시
  - 중복 제출 비활성화
  - 새 문제 만들기

완료 기준:

- 핵심 흐름이 로컬 또는 Preview 배포에서 동작합니다.
- 최소 2가지 화면 크기에서 레이아웃을 확인했습니다.
- 필요한 환경 변수가 문서화되어 있습니다.

## 10단계: Vercel 배포

- Preview 배포를 기본으로 진행합니다.
- Production 배포는 사용자가 명시적으로 요청한 경우에만 진행합니다.
- 배포 전에 `OPENAI_API_KEY` 등 필수 환경 변수를 확인합니다.
- 배포 완료 후 Preview URL을 공유합니다.

완료 기준:

- Vercel 배포 URL이 발급됩니다.
- 배포 URL에서 AI 기능(생성+평가)이 동작합니다.

## 11단계: 증빙 자료 준비

- 데스크톱/모바일 스크린샷, AI 기능 동작 스크린샷을 준비합니다.
- AI 코딩 도구 사용 과정 대화 로그 또는 스크린샷을 준비합니다.
- 증빙 자료에서 API 키가 노출되지 않았는지 확인합니다.

완료 기준:

- 제출용 스크린샷 1세트가 준비되어 있습니다.
- 제출 전 체크리스트를 통과했습니다.

## 결정된 사항

- AI 제공자: OpenAI로 통일 (문제 생성 + 평가)
- 답변 입력 방식: 텍스트 입력 (마이크 녹음 없음)
- MVP 문제 유형: Part3, Part5
- Part3 대화문: AI가 매번 새로 생성
- 평가 단위: 질문(문항)마다 개별 즉시 평가
- Langfuse 연동: MVP에 포함 (`/api/generate`, `/api/evaluate` 호출을 trace)
- 보너스 과제: Vercel Analytics(방문자 분석) 적용. `index.html`에 추적 스크립트를 삽입하고, 실제 수집은 Vercel 대시보드에서 프로젝트별로 활성화
