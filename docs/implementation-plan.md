# 구현 계획

## 전제

- 프론트엔드: 순수 HTML, CSS, JavaScript
- 프론트엔드 프레임워크: 사용하지 않음
- 백엔드: Vercel Serverless Functions의 Python
- API 위치: `api/index.py` (FastAPI 앱), 평가 로직은 `api/evaluate.py`
- 프론트엔드 호출 방식: `fetch('/api/evaluate')`
- 배포: Vercel
- 문제 출처: 로컬 정적 JSON
- AI 역할: 평가 전용
- MVP 난이도: 초급, 중급
- 작업 서비스명: TranslateUp

## 1단계: 프로젝트 구조 구성

- `index.html`을 추가합니다.
- `css/` 폴더를 추가합니다.
- `js/` 폴더를 추가합니다.
- `api/` 폴더를 추가합니다.
- `data/` 폴더를 추가합니다.
- `images/` 폴더를 추가합니다.
- `requirements.txt`를 추가합니다.
- `api/index.py`에 FastAPI 앱(top-level `app`)을 정의해 `/api/evaluate` 라우팅과 정적 파일 서빙을 함께 처리합니다.
- README를 제출 기준에 맞게 갱신할 준비를 합니다.

완료 기준:

- 과제에서 요구하는 프론트엔드와 백엔드 구조가 분리되어 있습니다.
- 로컬에서 정적 페이지를 열거나 간단한 서버로 확인할 수 있습니다.
- Python 백엔드 의존성 파일이 존재합니다.
- 루트 URL은 프론트엔드 `index.html`을 표시하고, API 경로만 Python 함수를 실행합니다.

## 2단계: 정적 문제 데이터와 공통 구조

- `data/exercises.json`을 추가합니다.
- 초급과 중급 문제를 충분히 넣습니다.
- JavaScript에서 문제 목록을 불러오거나 내장 데이터로 사용할 방식을 정합니다.
- 난이도별 문제 선택 로직을 추가합니다.
- 다음 문제 동작을 추가합니다.

완료 기준:

- 초급과 중급 문제를 사용할 수 있습니다.
- 선택한 난이도의 한국어 문장이 화면에 표시됩니다.
- 다음 문제 버튼이 같은 난이도의 다른 문제를 보여줍니다.

## 3단계: 한 페이지 영작 UI

- 서비스 소개 섹션을 만듭니다.
- 영작 연습 섹션을 만듭니다.
- AI 평가 결과 섹션을 만듭니다.
- 학습 안내 섹션을 만듭니다.
- FAQ 섹션을 만듭니다.
- 상단 메뉴 또는 고정 내비게이션으로 섹션 이동을 제공합니다.
- 반응형 레이아웃을 적용합니다.

완료 기준:

- 최소 3개 이상의 섹션이 있습니다.
- 메뉴 이동이 가능합니다.
- 사용자가 한 페이지에서 기본 흐름을 완료할 수 있습니다.
- 모바일과 데스크톱에서 레이아웃이 깨지지 않습니다.

## 4단계: 프론트엔드 상호작용

- 난이도 선택 UI를 구현합니다.
- 한국어 문제 표시 영역을 구현합니다.
- 영어 답변 입력 UI를 구현합니다.
- 평가 제출 버튼을 구현합니다.
- 입력 검증을 구현합니다.
- 로딩, 오류, 성공 상태를 구현합니다.
- 평가 결과를 원본 JSON이 아닌 사용자 친화적인 UI로 표시합니다.

완료 기준:

- 난이도 미선택 제출이 막힙니다.
- 빈 답변 제출이 막힙니다.
- 한글만 입력한 답변 제출이 막힙니다.
- 평가 중 중복 제출이 막힙니다.
- API 실패 메시지가 표시됩니다.

## 5단계: Python 평가 API

- `api/index.py`에 FastAPI 앱을 Vercel 함수 엔트리포인트로 구현합니다.
- `api/evaluate.py`에는 평가 로직을 둡니다.
- 요청 본문을 파싱합니다.
- 서버에서 입력값을 다시 검증합니다.
- 선택한 AI 제공자를 호출합니다.
- 구조화된 JSON 응답을 강제합니다.
- AI 결과를 정규화하고 검증한 뒤 클라이언트에 반환합니다.
- 필요한 Python 패키지를 `requirements.txt`에 정의합니다.

완료 기준:

- 유효한 요청은 평가 결과 JSON을 반환합니다.
- 잘못된 요청은 `400`을 반환합니다.
- 제공자 오류 또는 파싱 실패는 `500`을 반환합니다.
- API 키 누락은 통제된 서버 오류로 처리됩니다.
- 프론트엔드는 `fetch('/api/evaluate')`로 API를 호출합니다.

## 6단계: Langfuse 관측 준비

- Langfuse 연동 여부를 결정합니다.
- 연동하는 경우 최신 공식 문서를 확인합니다.
- `/api/evaluate` 호출을 trace 대상으로 설계합니다.
- 평가 프롬프트, 응답, 오류를 어떤 범위까지 저장할지 정합니다.
- 필요한 환경 변수를 문서화합니다.

완료 기준:

- Langfuse를 바로 붙일지 후순위로 둘지 결정되어 있습니다.
- 연동하는 경우 필요한 환경 변수와 관측 범위가 명확합니다.
- 개인정보나 민감한 학습 데이터 저장 정책이 명세에 반영되어 있습니다.

## 미결정 사항

- AI 제공자: OpenAI 또는 Gemini
- 시각적 톤: 집중형 학습 도구, 가벼운 학습 앱, 정돈된 제출용 웹 서비스 중 선택
- 평가 후 예시 답안을 따로 보여줄지 여부
- Langfuse 연동을 MVP에 포함할지 여부
- 보너스 과제 적용 여부
