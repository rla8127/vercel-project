# 사용자 흐름

## 기본 흐름

1. 사용자가 한 페이지 웹 앱에 접속합니다.
2. 사용자가 Hero 섹션에서 서비스 소개를 읽습니다.
3. 사용자가 시작 버튼을 누르거나 연습 영역으로 이동합니다.
4. 사용자가 Part3 또는 Part5 유형을 선택합니다.
5. 앱이 `/api/generate`로 문제 생성을 요청합니다.
6. 앱이 로딩 문구를 표시합니다: 문제를 만들고 있습니다.
7. 앱이 생성된 문제(Part3: 상황+대화문+질문 3개, Part5: 문제 상황)를 표시합니다.
8. 사용자가 문항별로 영어 답변을 작성합니다.
9. 사용자가 해당 문항의 평가 버튼을 누릅니다.
10. 앱이 클라이언트에서 입력값을 검증합니다.
11. 앱이 `/api/evaluate`로 해당 문항의 답변을 보냅니다.
12. 앱이 로딩 문구를 표시합니다: 답변을 평가하고 있습니다.
13. 앱이 해당 문항의 AI 평가 결과를 표시합니다.
14. 사용자가 다른 문항도 같은 방식으로 제출하고 평가받습니다.
15. 사용자가 새 문제 만들기 버튼을 누르면 같은 Part로 새 문제를 다시 생성합니다.

## 한 페이지 구성

첫 버전은 한 페이지 안에 다음 섹션을 배치합니다.

- Hero
- 문제 유형 선택 및 연습 (Part3 / Part5)
- AI 평가 결과
- 학습 안내
- FAQ

첫 화면에서는 서비스의 목적이 바로 드러나야 하며, 사용자가 곧바로 시작할 수 있는 행동이 있어야 합니다.

## 문제 생성 흐름

### Part3 선택 시

1. 사용자가 Part3 탭/버튼을 선택합니다.
2. 앱이 `/api/generate`에 `{ "part": "part3" }`를 보냅니다.
3. 응답으로 받은 상황 설명, 대화문, 질문 3개를 화면에 표시합니다.
4. 질문마다 별도의 답변 입력창과 "이 문항 평가받기" 버튼을 표시합니다.

### Part5 선택 시

1. 사용자가 Part5 탭/버튼을 선택합니다.
2. 앱이 `/api/generate`에 `{ "part": "part5" }`를 보냅니다.
3. 응답으로 받은 문제 상황을 화면에 표시합니다.
4. 단일 답변 입력창과 "평가받기" 버튼을 표시합니다.

## 입력 검증 흐름

### 문제 유형 미선택

발생 조건:

- 사용자가 Part를 선택하지 않고 진행하려고 합니다.

메시지:

```text
문제 유형을 선택해 주세요.
```

### 빈 답변

발생 조건:

- 사용자가 빈 값 또는 공백만 입력하고 평가받기를 누릅니다.

메시지:

```text
답변을 입력해 주세요.
```

### 한글만 입력한 답변

발생 조건:

- 사용자 답변에 한글은 있지만 영어 알파벳이 없습니다.

메시지:

```text
영어로 답변을 작성해 주세요.
```

### 중복 제출

발생 조건:

- 생성 또는 평가 요청이 진행 중일 때 사용자가 같은 버튼을 다시 누릅니다.

동작:

- 요청이 진행 중인 버튼을 비활성화합니다.
- 입력값은 그대로 유지합니다.
- 추가 API 요청을 보내지 않습니다.

## API 실패 흐름

발생 조건:

- `/api/generate` 또는 `/api/evaluate`가 오류를 반환합니다.
- OpenAI 호출이 실패합니다.
- AI 응답을 JSON으로 파싱할 수 없습니다.
- 요청이 타임아웃됩니다.

메시지:

- 생성 실패: `문제를 생성하지 못했습니다. 잠시 후 다시 시도해 주세요.`
- 평가 실패: `평가 중 오류가 발생했습니다. 잠시 후 다시 시도해 주세요.`

동작:

- 사용자가 입력한 답변을 유지합니다.
- 로딩 상태가 끝나면 다시 시도할 수 있게 합니다.
- 생성 실패 시 이전 문제 화면 상태를 유지합니다(빈 화면으로 만들지 않음).

## 결과 표시

UI는 원본 JSON을 그대로 보여주지 않습니다. 다음과 같은 형태로 문항별 평가 결과를 표시합니다.

```text
종합 점수: 78점

내용 적절성: 80점
문법: 75점
어휘: 78점

모범 답안
The speaker wants to have dinner at 7 PM this Friday at a new Italian restaurant downtown.

개선할 부분
at 7 -> at 7 PM

전체 피드백
질문에서 요구한 시간 정보는 정확히 답했지만 장소 설명이 다소 부족합니다.
```

개선할 부분이 없다면 수정이 필요 없다는 긍정 메시지를 표시합니다. Part3는 질문 3개 각각에 대해 이 결과 블록이 개별로 표시됩니다.
