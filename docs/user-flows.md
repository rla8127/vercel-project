# 사용자 흐름

## 기본 흐름

1. 사용자가 한 페이지 웹 앱에 접속합니다.
2. 사용자가 Hero 섹션에서 서비스 소개를 읽습니다.
3. 사용자가 시작 버튼을 누르거나 영작 연습 영역으로 이동합니다.
4. 사용자가 초급 또는 중급 난이도를 선택합니다.
5. 앱이 선택한 난이도에 맞는 한국어 문장을 표시합니다.
6. 사용자가 영어 답변을 작성합니다.
7. 사용자가 평가 버튼을 누릅니다.
8. 앱이 클라이언트에서 입력값을 검증합니다.
9. 앱이 `/api/evaluate`로 답변을 보냅니다.
10. 앱이 로딩 문구를 표시합니다: 답변을 평가하고 있습니다.
11. 앱이 AI 평가 결과를 표시합니다.
12. 사용자가 다음 문제 버튼을 누릅니다.
13. 앱이 같은 난이도의 다른 문장을 표시합니다.

## 한 페이지 구성

첫 버전은 한 페이지 안에 다음 섹션을 배치합니다.

- Hero
- 난이도 선택
- 영작 문제
- AI 평가 결과
- 학습 안내
- FAQ

첫 화면에서는 서비스의 목적이 바로 드러나야 하며, 사용자가 곧바로 시작할 수 있는 행동이 있어야 합니다.

## 입력 검증 흐름

### 난이도 미선택

발생 조건:

- 사용자가 난이도를 선택하지 않고 제출하려고 합니다.

메시지:

```text
난이도를 선택해 주세요.
```

### 빈 답변

발생 조건:

- 사용자가 빈 값 또는 공백만 입력하고 제출합니다.

메시지:

```text
영어 문장을 입력해 주세요.
```

### 한글만 입력한 답변

발생 조건:

- 사용자 답변에 한글은 있지만 영어 알파벳이 없습니다.

메시지:

```text
영어로 답변을 작성해 주세요.
```

### 중복 제출

발생 조건:

- 평가 요청이 진행 중일 때 사용자가 다시 제출 버튼을 누릅니다.

동작:

- 제출 버튼을 비활성화합니다.
- 답변 입력란은 그대로 보여줍니다.
- 추가 API 요청을 보내지 않습니다.

## API 실패 흐름

발생 조건:

- `/api/evaluate`가 오류를 반환합니다.
- OpenAI 또는 Gemini 호출이 실패합니다.
- AI 응답을 JSON으로 파싱할 수 없습니다.

메시지:

```text
평가 중 오류가 발생했습니다. 잠시 후 다시 시도해 주세요.
```

동작:

- 사용자의 답변을 유지합니다.
- 로딩 상태가 끝나면 다시 시도할 수 있게 합니다.
- 자동으로 다음 문제로 넘어가지 않습니다.

## 결과 표시

UI는 원본 JSON을 그대로 보여주지 않습니다. 다음과 같은 형태로 평가 결과를 표시합니다.

```text
종합 점수: 85점

의미 전달: 90점
문법: 85점
자연스러움: 80점

추천 문장
I meet my friends every weekend.

수정할 부분
my friend -> my friends

전체적으로 의미는 잘 전달됐습니다.
```

수정할 부분이 없다면 수정이 필요 없다는 긍정 메시지를 표시합니다.
